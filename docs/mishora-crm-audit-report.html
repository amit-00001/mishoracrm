Executive Summary (original, unchanged)

The core CRM, sales, finance, public booking, ticketing, inventory, purchasing, HR setup, and notification flows are reachable and several complete successfully. The highest-risk defects are broken form persistence, a ticket-create server error, purchase/work-order requests that hang, and inconsistent permission enforcement.

Severity is based on user impact and whether a workflow is blocked: P1 = critical blocker, P2 = high-impact defect, P3 = moderate, P4 = cosmetic/low risk.

Findings

Fixed

P1Purchase request approval hangs

Steps: Open tenant 4 purchase request 2 and submit the approval action.

Expected: The request is approved and the user returns to the detail/list page.

Actual: The request remained pending and the browser tab was unresponsive for more than 60 seconds.

Route: /purchase-requests/2 · Requests 1 and 2 were also created after an empty submission race.
Fixed

P1Work-order material issue hangs

Steps: Open work order 1 and choose Start & Issue Materials.

Expected: Materials are issued, inventory is updated, and the work order advances.

Actual: The request remained unresponsive for more than 60 seconds.

Route: /work-orders/1 · Work order uses QA product 1 and raw material 2.
Fixed

P1Ticket creation returns a server error

Steps: Open the tenant Tickets page and select Create Ticket.

Expected: A ticket form opens.

Actual: /tickets/create returns 500 SERVER ERROR. Public support ticket submission still worked.

Fixed

P2Lead edit silently clears fields

Steps: Edit lead 2, change a visible field, and save.

Expected: Only the changed field is updated.

Actual: Company, designation, city, state, and value previously present were cleared. Assignment also displayed as Unassigned despite selecting Test Operator.

Fixed

P2Contact lead relationship does not persist

Steps: Edit contact 4 and select lead 2.

Expected: The contact detail shows the selected linked lead.

Actual: The detail page shows LINKED LEAD Not provided.

Fixed

P2Deal edit loses expected close date and keeps wrong win probability

Steps: Edit deal 3 and move it to Won.

Expected: Existing expected close date is retained and Won uses the final probability.

Actual: Expected close date was cleared unless manually restored; Won retained 10% probability instead of 100%.

Fixed

P2Empty purchase request submission has no validation and races

Steps: Submit the new purchase request form with required fields empty.

Expected: Inline validation prevents submission.

Actual: No validation appeared. A delayed request later created an additional valid-looking record, leaving duplicate requests 1 and 2.

Fixed

P2Staff attendance clock-in submits an empty staff ID

Steps: Log in as Test Staff 20260926 and open Attendance → Clock In/Out.

Expected: Clock In creates an attendance record for the logged-in staff member.

Actual: The hidden staff_id field is empty. Clicking Clock In leaves the row at Not marked.

Fixed

P2Permission enforcement is inconsistent

Custom role qa_auditor had four permissions. Staff correctly received 403 responses on /roles and /audit-logs, but /leads/create remained accessible despite the role lacking create permission.

Fixed

P2Time tracking form exposes raw JSON

Start and stop actions succeeded at the API level, but browser form submission navigated to raw JSON responses such as {"ok":true,"id":1} instead of redirecting back to the time-tracking page. The completed entry was then visible after manual navigation.

Fixed

P3Two navigation links point to 404 routes

The sidebar links /time-tracking and /reports return 404. Their actual working routes are /time-entries and /reports/overview.

Fixed

P3Public booking needs separate service enablement

Public booking was enabled, but the first public page showed no bookable services until the service was separately enabled. After that change, slots displayed and a public booking completed successfully.

Fixed

P3Invalid login has no visible error message

Submitting invalid credentials returned to the login page without a visible “credentials do not match” message. A separate retry with a known wrong password did show that message, indicating inconsistent or timing-dependent feedback.

Reviewed

P4Portal test credential and typo exposure

Superadmin Portal Customers displayed test login values (phone 9999999999, OTP 123456) and an existing customer email shown as test@gmai.com. Confirm whether these are intentionally seeded demo values.

Fixed

P4Plans page GST field has stray percent text

A stray % was visible beside the GST field on the Superadmin Plans page.

The log includes pre-existing timeout, SQL, and controller failures. These should be triaged separately from defects introduced by this audit.
